## 0. 先に共有したい調査結果

### SAPの試験が新しい版に切り替わった
- **2026-11-17 から SAP-C03 に切り替わった**（SAP-C02 は 11-16 まで）。出題分野が丸ごと変わっている
- 公式の試験ガイド（日本語版）による SAP-C03 の内容
  - 採点される問題 65問 ＋ 採点されない問題 10問（合計75問）
  - 問題の形式：単一選択（4択）と複数選択（**5つ以上の選択肢から2つ以上**を選ぶ）の2種類だけ
  - 合格スコア 750（100〜1,000 のスケールスコア）
  - 試験時間は試験ガイドに書かれていない → 公式の認定ページで確認してから入れる
- SAP-C03 の出題分野（日本語版の試験ガイドの表記そのまま）

| 分野 | 名前 | 比重 |
|---|---|---|
| 1 | クラウド向けに構築されたアーキテクチャの設計と実装 | 25% |
| 2 | セキュリティ、コンプライアンス、ガバナンス | 25% |
| 3 | コストを最適化したアーキテクチャの設計 | 15% |
| 4 | 回復力、移行、事業の継続性 | 15% |
| 5 | 運用上の優秀性とオートメーション | 20% |

- **今の3問は SAP-C02 の分野名を使っている**ので、移行のときに付け替える案

| 問題 | 内容 | 新しい分野 |
|---|---|---|
| sap-001 | SCPでリージョンを制限 | 2 セキュリティ、コンプライアンス、ガバナンス |
| sap-002 | 移行前の調査（Application Discovery Service） | 4 回復力、移行、事業の継続性 |
| sap-003 | マルチAZで可用性を上げる | 4 回復力、移行、事業の継続性 |

- sap-002 は「4択から2つ選ぶ」形式。C03 の複数選択は「5つ以上から選ぶ」なので、選択肢を1つ足して本番の形式に合わせる

## 1. データ構造の変更案

### assets/exams.json

いただいた例をベースに、3点だけ変えています（理由は下）。

```json
{
  "exams": [
    {
      "id": "sap",
      "code": "SAP-C03",
      "shortName": "SAP",
      "name": "Solutions Architect - Professional",
      "nameJa": "ソリューションアーキテクト - プロフェッショナル",
      "level": "professional",
      "status": "available",
      "domains": [
        { "id": "d1", "name": "クラウド向けに構築されたアーキテクチャの設計と実装", "weight": 25 },
        { "id": "d2", "name": "セキュリティ、コンプライアンス、ガバナンス", "weight": 25 },
        { "id": "d3", "name": "コストを最適化したアーキテクチャの設計", "weight": 15 },
        { "id": "d4", "name": "回復力、移行、事業の継続性", "weight": 15 },
        { "id": "d5", "name": "運用上の優秀性とオートメーション", "weight": 20 }
      ],
      "mock": { "questionCount": 75, "timeLimitMinutes": 180 },
      "guideUrl": "https://docs.aws.amazon.com/ja_jp/aws-certification/latest/solutions-architect-professional-03/solutions-architect-professional-03.html"
    }
  ]
}
```

| 変更点 | 理由 |
|---|---|
| `code` を `SAP-C03` のように**版まで**入れ、画面用に `shortName` を分ける | 今回のように版が変わったとき、古い版の問題が混ざっていないかをチェックできるようにするため |
| 分野を文字列ではなく `{ id, name, weight }` にする。問題側は `"domain": "d2"` のようにIDで参照する | 分野名は長く、表記ゆれ（読点の有無など）でズレやすい。IDなら名前を直しても問題側を書き換えなくて済む。Laravelでいう、名前ではなく外部キーで紐付ける考え方 |
| 分野に `weight`（比重）を持たせる | 模試で、本番の比重どおりに分野ごとの問題数を配分するのに使う |
| `status`（`available` / `retiring`）を追加 | 終了予定の試験に「◯月で終了」と表示するため |

- 「準備中」は、**`assets/questions/<id>.json` があるかどうかで自動で判定**する（フラグを別に持つと、ファイルを足したのにフラグを直し忘れる、が起きるため）
- 模試の問題数・時間は試験ごとの設定値。数字は公式の試験ガイドと認定ページで確認して入れる

### assets/questions/sap.json

いただいた例のとおり。ファイルの先頭に、どの版の問題かを書く項目だけ足します。

```json
{
  "examId": "sap",
  "examCode": "SAP-C03",
  "questions": [
    {
      "id": "sap-001",
      "domain": "d2",
      "question": "...",
      "choices": [
        { "text": "選択肢A", "explanation": "Aが不正解の理由" },
        { "text": "選択肢B", "explanation": "Bが正解の理由" }
      ],
      "answers": [1],
      "explanation": "全体のまとめ解説",
      "references": [
        { "title": "サービスコントロールポリシー (SCP)", "url": "https://docs.aws.amazon.com/ja_jp/organizations/latest/userguide/orgs_manage_policies_scps.html" }
      ]
    }
  ]
}
```

### 学習記録（端末内に保存）

| 保存するもの | 中身 |
|---|---|
| 回答の記録 | 問題ID、試験ID、分野ID、正誤、回答した日時、モード（練習／模試） |
| 模試の結果 | 試験ID、日時、問題数、正解数、かかった時間、分野ごとの正解数 |
| 取得済みの試験 | 試験IDと、印をつけた日 |

- 分野ごとの正答率は「**各問題の最新の回答**」で計算する案（最初に間違えた問題も、解き直して正解すれば正答率に反映される。今の実力に近い数字になる）

## 2. 画面構成

```
ホーム（試験一覧）
 ├ 上部：全冠の進捗「3 / 12 取得」＋バー
 ├ Foundational / Associate / Professional / Specialty の見出しごとにカード
 │   カード：SAP・正式名・収録数 or「準備中」・正答率・取得済みバッジ
 └ 右上メニュー：表示モード、広告のプライバシー設定
     ↓ タップ
試験トップ
 ├ 試験名・版（SAP-C03）・「取得済みにする」切り替え
 ├ 分野の一覧：分野名・問題数・正答率
 └ ボタン：「全分野から出題」「分野を選んで出題」「模試（75問・180分）」
     ↓
出題画面（今の QuizScreen を拡張）
 ├ 練習モード：今と同じ流れ ＋ 選択肢ごとの解説 ＋ 根拠リンク
 └ 模試モード：残り時間を表示、1問ごとの正誤は出さない、前の問題に戻れる、未回答の一覧
     ↓
結果画面
 ├ 練習：正答数と分野ごとの内訳
 └ 模試：正答率・かかった時間・分野ごとの正答率・間違えた問題の一覧（タップで解説）
```

画面の補足
- **回答後の解説**：選んだ選択肢の解説を一番上に、色付きの枠で出す → その下にほかの選択肢の解説 → まとめ解説 → 「根拠：〜」のリンク
- **模試の採点**：本番のスケールスコア（750点など）は計算方法が公開されていないので、**「正答率◯%」で表示**する。点数風の数字を出すと誤解されるため
- **模試の問題が足りないとき**：今はSAPが3問しかないので、「収録数が足りないため、3問で実施します」と表示して、ある分だけで実施する
- **模試の残り時間**：開始した時刻から計算する（アプリを裏に回しても時間がズレないようにするため）
- **広告**：模試の途中には全画面広告を出さない。結果画面に進むときに1回だけ（今と同じルール）
- **表示モードの切り替え**（タブ／スワイプ）はそのまま残す

## 3. UIの方向性

- 白基調でミニマル、余白多め、角丸のカード。アクセントカラーは1色
- アクセントカラーは**ティール（青緑）**を提案。AWSのオレンジと紺は、AWSの公式アプリと誤解されやすいので避ける（商標の方針に合わせる）
- 長文の読みやすさを最優先：問題文は17pt・行間1.7倍くらいを基準にして、シミュレーターで見ながら調整する
- フォントは端末標準（iPhoneならヒラギノ）を使う。フォントを同梱するとアプリが数MB重くなり、ネットから取ってくる方法は通信が発生するため
- ダークモードは端末の設定に合わせて自動で切り替える
- 画面上の表記は「クラウド認定」。試験名（SAP、SAAなど）はそのまま使う

## 4. 追加するパッケージ（案）

| パッケージ | 使い道 | 理由 |
|---|---|---|
| `url_launcher` | 根拠リンクをタップしてブラウザで開く | Flutterの公式パッケージで、リンクを開く定番 |
| `sqflite` | 学習記録の保存 | 下で比較 |

学習記録の保存先の候補

| 候補 | 特徴 | 判断 |
|---|---|---|
| `shared_preferences`（導入済み） | キーと値を保存するだけ | 設定の保存には向くが、回答の記録が増えると集計しづらい |
| **`sqflite`** | 端末内のSQLite。SQLをそのまま書く | **おすすめ。** 分野ごとの正答率は `GROUP BY` で出せる。SQLに慣れているので学習コストが低い。コードの自動生成も要らない |
| `drift` | SQLiteを型付きで扱える（Eloquentに近い） | 便利だが、コードの自動生成（build_runner）を覚える必要がある。規模が大きくなってから考えればよい |
| `hive_ce` など | キーと値の高速な保存 | 集計がSQLより面倒 |

- 取得済みの印や表示モードのような小さい設定は、今の `shared_preferences` のまま
- 画面の移動は Flutter 標準の `Navigator` で足りる（4画面なので、ルーティング用のパッケージは入れない）
- 状態管理も今の `setState` のままにする。画面ごとのデータ読み込みはリポジトリ（Laravelでいうリポジトリ層）に寄せる

## 5. 品質チェックのスクリプト

`dart run tool/validate_questions.dart` で全試験の問題をチェックする。

- いただいた5項目
  - 全問に根拠リンクが1つ以上ある
  - 全選択肢に解説がある
  - answers のインデックスが choices の範囲内にある
  - id の重複がない（全試験を通して）
  - domain が exams.json に定義された分野と一致している
- 追加したい項目
  - 根拠リンクの URL が一次情報のドメイン（`docs.aws.amazon.com`、`aws.amazon.com`、`d1.awsstatic.com`）か
  - 問題ファイルの `examCode` が exams.json の版と一致しているか（古い版の問題の混入を防ぐ）
  - 単一選択は4択、複数選択は5つ以上の選択肢か（本番の形式に合わせる。違反は警告だけ）
- 同じチェックを `flutter test` からも呼んで、テストを回すたびに確認されるようにする

## 6. 実装の順番

いただいた順番をベースに、2か所だけ入れ替えています。各ステップの最後に `flutter analyze`・`flutter test`・シミュレーターでの確認をして、コミットしてから次に進みます。

| # | 内容 | 主な作業 |
|---|---|---|
| 0 | 試験情報の確認 | 公式の認定ページと各試験ガイドで、試験一覧・版・分野・問題数・時間を確認し、`exams.json` の中身を作る |
| 1 | **複数試験の土台** | Exam・Domain・Question のモデル、ExamRepository、問題データの新形式への移行（3問）、ホームと試験トップの最低限の画面、**テーマの土台（ライト・ダーク・文字サイズ）** |
| 2 | 解説・根拠 | 選択肢ごとの解説、根拠リンク（`url_launcher`）、品質チェックのスクリプト |
| 3 | 分野別の出題 ＋ **学習記録の保存** | 分野を選んで出題、回答を `sqflite` に保存、試験トップに問題数と正答率を表示 |
| 4 | 模試 | 問題数・時間の設定、比重どおりの配分、タイマー、まとめて採点、分野別の結果、間違えた問題の見直し |
| 5 | 全冠の進捗 | 取得済みの印、ホームの進捗表示 |
| 6 | UIの仕上げ | 余白・カード・色・行間の調整、ダークモードの見た目の確認 |
| 7 | ドキュメント | `docs/handoff.md` と `CLAUDE.md` を全試験対応に合わせて更新 |

入れ替えた理由
- **学習記録の保存を、5（全冠の進捗）から3に前倒し**：試験トップに分野ごとの正答率を出すには保存が先に要るため。模試の結果の保存にも使う
- **テーマの土台を1に入れる**：色と文字の設定を最初に決めておけば、2〜5で作る画面が最初からその見た目になる。最後にまとめて直すより手戻りが少ない。6では細かい調整だけをする

## 7. 確認したいこと

1. SAP は **SAP-C03 の分野で作り直す**。今の3問の分野の付け替えと、sap-002 に選択肢を1つ足すことでよいか
2. 分野を **ID（d1〜d5）で参照する形**に変えてよいか（いただいた例からの変更）
3. 学習記録の保存は **`sqflite`**、リンクは **`url_launcher`** でよいか
4. 実装の順番の入れ替え（学習記録の前倒し、テーマの土台を1に）でよいか
5. アクセントカラーは**ティール**でよいか
6. 試験一覧に入れる範囲
   - 案：今受けられる試験だけを入れる。終了予定の試験は「◯月で終了」と表示し、終了日を過ぎたら外す。ベータ版の試験は入れない
   - 全冠の「全試験数」もこの範囲で数える
